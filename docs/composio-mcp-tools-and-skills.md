# Composio MCP Tools and Skills

## MCP servers in this environment

Two Composio-backed MCP servers are attached:

| Server | Name | Tools | Extra |
|--------|------|-------|-------|
| `user-composio` | composio | 7 meta tools | Flat parameter style |
| `user-rube` | rube | 11 tools + 7 prompts | `params` wrapper; adds recipe and schedule support |

Both share the same core workflow; Rube extends it with recipes and built-in prompts.

---

## Confirmed meta tools (user-composio)

| Tool | Purpose |
|------|---------|
| `COMPOSIO_SEARCH_TOOLS` | Discover tools for a use case; returns schemas, connection status, execution plan, pitfalls, and a `session_id`. |
| `COMPOSIO_GET_TOOL_SCHEMAS` | Fetch full input schemas when SEARCH returned only a `schemaRef`. |
| `COMPOSIO_MANAGE_CONNECTIONS` | Check or create app connections; returns auth URL if needed. |
| `COMPOSIO_WAIT_FOR_CONNECTIONS` | Poll until auth reaches ACTIVE/FAILED after showing an auth link. |
| `COMPOSIO_MULTI_EXECUTE_TOOL` | Execute 1-50 tools in parallel; only for independent, schema-compliant calls. |
| `COMPOSIO_REMOTE_BASH_TOOL` | Run bash in a remote sandbox for simple file/data processing. |
| `COMPOSIO_REMOTE_WORKBENCH` | Run Python in a persistent remote Jupyter sandbox for bulk ops and large data. |

## Rube-only extras (user-rube)

| Tool | Purpose |
|------|---------|
| `RUBE_FIND_RECIPE` | Search recipes by natural language. |
| `RUBE_EXECUTE_RECIPE` | Run a recipe by ID. |
| `RUBE_CREATE_UPDATE_RECIPE` | Save a workflow as a reusable recipe/notebook. |
| `RUBE_GET_RECIPE_DETAILS` | Inspect a recipe by ID. |
| `RUBE_MANAGE_RECIPE_SCHEDULE` | Schedule recurring recipe runs. |

Rube also has 7 pre-built prompts: `gh-prs`, `gh-review-pr`, `mail-archive`, `calendar-view`, `slack-channel-insights`, `search-to-notion`, `get-started`.

## Canonical execution order

```
1. SEARCH_TOOLS        → discover tools, get session_id, review plan
2. GET_TOOL_SCHEMAS    → (only if schemaRef, not full schema)
3. MANAGE_CONNECTIONS  → (only if toolkit not active)
4. WAIT_FOR_CONNECTIONS → (immediately after showing auth URL)
5. MULTI_EXECUTE_TOOL  → execute with schema-compliant args
6. REMOTE_WORKBENCH    → (only for large data or bulk ops)
7. REMOTE_BASH_TOOL    → (only for simple remote shell processing)
```

**Critical rules:**
- Carry `session_id` through every meta tool call.
- Never invent tool slugs, parameters, or toolkit names.
- Batch only independent tools in MULTI_EXECUTE.
- Review the execution plan and pitfalls from SEARCH before acting.
- Analyze small responses inline; escalate to workbench only when needed.

## Terminology: Cursor skills vs Composio skills vs Recipes

These are three different things:

| Term | What it is | Where it lives |
|------|-----------|----------------|
| **Cursor skill** | A markdown instruction file (`SKILL.md`) that teaches the Cursor agent how to perform a task. | `~/.cursor/skills/` (personal) or `.cursor/skills/` (project). |
| **Composio skill** (MCP) | A Python Pydantic code artifact generated by the `Create / Update Skill from Workflow` MCP tool after executing a workflow. | Composio platform. |
| **Composio recipe** | A reusable workflow notebook created or found via `RUBE_CREATE_UPDATE_RECIPE` / `RUBE_FIND_RECIPE`. | Composio platform. |

The personal **Cursor skill pack** for Composio is at `~/.cursor/skills/composio-*`. These skills teach Cursor the correct workflow and rules for the seven meta tools.

## Best practices

- **Search first.** Always start with SEARCH_TOOLS for new workflows.
- **Honor session_id.** Pass it to every subsequent meta tool call.
- **Restrict toolkits** for coding agents. Use `toolkits=["github"]` in sessions.
- **Prefer inline analysis.** Only escalate to workbench/bash for large or bulk data.
- **Schema safety.** Never guess tool inputs; fetch schemas if needed.
- **Permission mode.** Use `"default"` in production; `"bypassPermissions"` is for demos.
